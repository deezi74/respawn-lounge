# Regular posts integration contract

Types: shared/post-types.ts exports RegularPost, PostPhoto and POST_LIMITS. Existing types/helpers unchanged.

Backend server/features/posts.ts exports registerPostRoutes(app). Registered by parent in server/_core/index.ts. All JSON responses for a post use RegularPost, explicit whitelist serialization, never raw storage keys. All mutations same-origin authenticated and confirmed:true. Every request rechecks current Lounge privacy/membership, including photo delivery and share view. Public Lounge posts public only if Lounge still public; private posts never broaden. Owner retained access while private Lounge membership still required for nonowners. Profile is public.

GET /api/app/posts returns RegularPost[] newest first (max 50 accessible). Optional loungeId, ownerId filters; unauthorized lounge filters return 404 (not leaked data). GET /api/app/posts/:id returns RegularPost or 404 inaccessible.
POST /api/app/posts accepts multipart FormData in this order: text, destination ('profile'|'lounge'), loungeId (optional), confirmed ('true'), then photos files (0..4). It may also accept JSON for text-only. User and Lounge destination must be authorized before accepting photo bytes. Reject empty text+no photos, >5000 chars, invalid/unsupported images or >8 MiB each. Decode/reencode static JPEG/PNG/WebP with Sharp, EXIF rotation and metadata stripped, bounded pixels/dimensions. Persist opaque keys + dimensions in raw post record, return application-owned photo URLs only. Return created RegularPost with HTTP 201.
PATCH /api/app/posts/:id accepts {text:string,keepPhotoIds:string[],confirmed:true}, author only, destination immutable; reject unknown photo IDs or empty result. Return updated RegularPost. DELETE /api/app/posts/:id accepts {confirmed:true}, author only, soft delete and return {deleted:true}. Deleted/removed photo cannot be read via old URLs.
GET /api/media/post-photo/:postId/:photoId authenticates ordinary session or an exact-resource ticket (mediaTicket/ticketUser existing), rechecks post/photo ACL. Stream sanitized image/webp from storage without redirects/keys; Cache-Control private,no-store. Public photos may be read anonymously; no private/API caching in SW.

Frontend owned agent: client/src/components/lounge/Posts.tsx plus client/src/components/lounge/posts.css. Export PostComposer({lounges:Lounge[],userName?:string,initialLoungeId?:string,onClose:()=>void,onCreated?:(post:RegularPost)=>void}); PostFeed({ownerId?:number,loungeId?:string,search?:string,title?:string,onCreate?:()=>void,compact?:boolean}); PostPage({id:string}); PostPrompt({onCreate:()=>void,userName?:string}). Composer uses api/POST multipart, refreshes app queries and closes on success. Feeds use useData identity-partitioned queries, real author/time/privacy, photo enlargement, share link /post/id, author-only text edit/photo-removal and confirmed deletion. Limit feedback, preserved errors, busy disable/close and revoke blob previews. Existing Modal/Confirm/Field helpers may be reused. Neon colors via existing CSS vars and responsive styles in dedicated imported posts.css. Main parent owns Home.tsx integration, App.tsx /post route and route manifest.
